## Step 4 – Analysis

- `loganalyzer/analysis.py`: a `Stats` class filled one event at a time with `add()`, so the same code works for a whole log and later for the live stream (Step 9). `summarize(events)` is a thin wrapper that feeds a list into a new `Stats`.
- Everything is counted with `collections.Counter`; pandas would be overkill here.
- Totals: `failed` and `accepted`, both weighted by `count` (a `message repeated N times` line counts as N).
- `top_ips()`, `top_users()` – failed attempts only; a successful login does not push an IP up the list.
- `top_invalid_users()` – names that do not exist on the system, from `Invalid user` lines. They are not added to `failed`, because the same attempt already has its own `Failed password for invalid user` line.
- `hourly_series()` – every hour from the first to the last failed attempt, including hours with zero, so the chart in the TUI has no gaps.
- Deviation from the guide: the guide counts `accepted += 1`; the code uses `count` for consistency with `failed`.
- `tests/test_analysis.py`: 9 tests (repeated count, invalid user not counted as failed, top lists, accepted not in top IPs, zero-filled hours, `add()` one by one equals `summarize()`, empty stats, both sample files). All 23 tests pass.

## Step 5 – Fetching over SSH

- `loganalyzer/fetcher.py`: a `Runner` protocol with two implementations, so the rest of the program does not know where the lines come from:
  - `SSHRunner` (paramiko): `RejectPolicy` for unknown hosts, a 10 s connect timeout, a 60 s command timeout, usable as a context manager. Output is read before `recv_exit_status()` so a large output cannot block.
  - `LocalRunner` (`bash -c`): the same commands locally, for development and tests without a network.
- Every failure becomes a `FetchError` with a readable message. The `except` order matters: `BadHostKeyException` and `AuthenticationException` are subclasses of `SSHException`; `socket.timeout` and `NoValidConnectionsError` are subclasses of `OSError`.
- Filtering on the server: `grep_command()` builds `grep -E -- <pattern> <path>` with `shlex.quote` on both inputs. `fetch_lines()` accepts grep exit code 1 (no matches) as success. `SUMMARY_PATTERN = "Failed|Accepted|Invalid user"` is the default for the summary.
- `tests/test_fetcher.py`: 7 tests. They cover quoting, local fetch equal to the file's matching lines, no match giving `[]`, a missing file giving `FetchError`, injection in the path (`; touch <marker>`) not executed, the pattern `-r` not treated as an option, and a refused connection giving `FetchError`. All 30 tests pass.

Error messages checked by hand:

Stats over them: 28 failed, 9 accepted, all from `127.0.0.1`. The injection path `/var/log/auth.log; touch /tmp/pwned-test` produced `grep: ...: No such file or directory` and the file was not created.

## Findings

- The parser counts lines (20 failed events in `sample_auth.log`), while Stats counts attempts (22). The difference is exactly the `message repeated` lines, so both numbers are correct and the README/defense should say which one is meant.
- paramiko logs authentication failures with a full traceback from its transport thread, even though the same failure also arrives as an exception. A `NullHandler` on the `paramiko` logger keeps the output to the one `FetchError` line.

## Issues

- The SSH login stopped working: the desktop keyring agent refused to sign with the key ("agent refused operation"), and the key's passphrase was forgotten, so `ssh localhost` fell back to a password prompt. Fixed by replacing the key: the old pair was kept as `~/.ssh/id_ed25519.old`, a new ED25519 key was created with `ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ""` and copied to `authorized_keys`. The key has no passphrase, which is acceptable because it only opens `localhost`. GitHub uses HTTPS, so it is not affected.
- With `-f` the full path is given, so the earlier mistake (a bare file name saving the key in the current directory) cannot happen again.
