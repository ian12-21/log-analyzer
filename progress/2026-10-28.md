## Step 3 – Parser

- `loganalyzer/parser.py`: frozen `Event` dataclass, a header regex for both timestamp formats and both process names, message regexes (`Failed`, `Accepted`, `Invalid user`), `message repeated N times` handling (`count`), `parse_timestamp()` with year rollover, `parse_line()` and `parse_lines()` (sorted by time).
- `now` is a parameter, so tests are reproducible.
- Counting decision: only `failed` counts as a failed attempt; `invalid_user` is kept for user-name statistics (a non-existent user produces both lines for one attempt).
- `tests/test_parser.py`: 14 tests, all passing (formats, IPv6, empty user name, ignored lines, repeated count, December/January rollover, both sample files).
- Added `pytest.ini` (`pythonpath = .`) so `pytest` finds the package from the project root.
- Result on samples: `sample_auth.log` → 20 failed, 7 accepted, 2 invalid_user; `attack_auth.log` → 15 failed from the attacker IP followed by a successful root login.

## Findings

- This system writes `auth.log` with ISO 8601 timestamps (`2026-10-28T22:46:27.469775+01:00`), not the classic `Oct 28 22:46:27` format. The parser has to support both.
- OpenSSH 9.6 logs as `sshd[...]`; versions 9.8+ use `sshd-session[...]`. The parser has to accept both process names.
- A `message repeated N times` line stands for N additional events, so the parser must extract the count.

## Issues

- `ssh-keygen` saved the key in the current directory because a bare file name was entered at the prompt; `ssh-copy-id` then reported "No identities found". Fixed by moving the key to `~/.ssh/id_ed25519` (the default name also lets paramiko find it automatically).
- Logging in with the key skips the password prompt, so failed-password events for an existing user were generated with `ssh -o PubkeyAuthentication=no`.
